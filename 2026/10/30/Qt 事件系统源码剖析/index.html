Qt 事件系统源码剖析

Qt 事件系统源码剖析

Qt 事件系统是整个框架的”邮局”：**QEvent 是包裹，postEvent 是往信箱投递，exec() 是永不停转的分拣流水线，event() 是收件人签收**。上一篇《信号槽源码剖析》里 Queued 连接的”寄信”机制，寄的就是 QEvent::MetaCall 这个包裹——它走的正是本文这条链路。源码以 Qt5 为准（略去无关样板），配中文注释对照。

1. 事件是什么，从哪来

QEvent 只是一个带 type() 枚举的普通 C++ 对象，派生出 QMouseEvent、QKeyEvent、QTimerEvent、QMetaCallEvent 等具体包裹。常见类型：

类型 谁产生的
MouseButtonPress / KeyPress / Paint 系统平台消息，由 QPA 平台层转换
Timer QTimer/startTimer 超时
MetaCall Queued 信号槽调用（上一篇）
DeferredDelete deleteLater()
Quit / Close 应用退出、窗口关闭

事件有个 spont 标记区分”户口”：**系统消息进来的是 spontaneous=true（自发的），应用自己 post 的是 false**——event->spontaneous() 可查。

2. 两条投递路径：直达 vs 入队

postEvent 则是异步投递——投进 receiver 归属线程的队列后立刻返回：

要点：事件必须堆分配——队列接管所有权，投递完即不可再访问；它是 Qt 唯一线程安全的事件通信方式（sendEvent 跨线程调会直接出事）。

3. 事件循环 exec：永不停转的分拣线

processEvents 委托给线程的 QAbstractEventDispatcher（Windows 是 QEventDispatcherWin32，Unix 是 glib/select 实现），每轮迭代统一处理四类货色：

货源 说明
系统消息 平台窗口消息 → 转成 QEvent 走 sendSpontaneousEvent 直达
posted events postEventList 里的队列 → sendPostedEvents 逐个派发
定时器 到期产生 Timer 事件
socket/其他 notifier QSocketNotifier、管道等

quit()/exit() 只是把 d->exit 置位并唤醒 dispatcher，下一轮循环自然退出。事件循环不跑，队列里所有 posted 事件就一直堆积——Queued 槽不执行、timer 不触发、deleteLater 不释放，全是同一个原因。

4. 派发链：队列 → notify → event() → handler

出队：sendPostedEvents

细节：insertionOffset 保证本轮只送到当前已有的件——派发过程里新投递的事件下一轮才处理，防止活锁；锁在 sendEvent 前先放掉，避免槽里再 postEvent 死锁。

分发：notify → 过滤器 → event()

签收：event() 的二级分发

QWidget::event() 再做一层分发：MouseButtonPress → mousePressEvent()、KeyPress → keyPressEvent()、Paint → paintEvent()。所以我们平时”重写 xxxEvent“重写的其实是分发终点；写 event() 能在所有 handler 之前截获一切。

5. 事件过滤器：签收前的拦截

installEventFilter(obj) 后，obj 的 eventFilter(watched, event) 会在 watched->event() 之前被调——返回 true 表示吞掉，事件不再往下走。

  • 两级过滤：qApp->installEventFilter 装的过滤器对全应用生效（且只能在主线程）；普通 installEventFilter 只对所监视的对象生效；
  • 多过滤器逆序：后安装的先执行；
  • 典型用途：全局快捷键、给”不是自己的控件”改行为、调试打印事件流。

6. 关键细节速查

机制 说明
事件传播 QWidget 的 handler ignore() 后，事件沿父 widget 链继续上抛（parent()->event()）；accept 才终止
事件压缩 compressEvent：连续的 Paint/UpdateRequest/Resize 合并成一份，避免重绘风暴
DeferredDelete 层级 deleteLater 在嵌套 exec()（如 modal 对话框、手动 processEvents）下有 loopLevel+scopeLevel 保护——内层循环不会删外层循环还在用的对象
processEvents() 手动抽一轮水泵：长任务里调它能保持 UI 响应，但会重入事件处理（按钮可能被重复点击），配合 ExcludeUserInputEvents 或禁用 UI 使用
跨线程只能 postEvent sendEvent 要求 receiver 在当前线程；跨线程通信唯一安全姿势就是 postEvent（Queued 信号槽正是这么做的）
removePostedEvents 从队列摘除未派发的事件（不是派发），对象析构时自动清理自己的残留

        P2["sendEvent()<br/>同步直达，spont=false"]
        P3["系统消息 → sendSpontaneousEvent()<br/>同步直达，spont=true"]

        Q["threadData.postEventList<br/>按优先级排序的队列"]
        L["QEventLoop::exec()<br/>while(!exit) processEvents()"]
        D["sendPostedEvents()<br/>逐个取出 → sendEvent()"]
        N["notifyInternal2 → notify()<br/>→ notify_helper()"]
        F{"两级过滤器<br/>qApp 级 → receiver 级"}
        E["receiver->event()<br/>switch(type) 分发"]
        H["具体 handler<br/>timerEvent / placeMetaCall<br/>mousePressEvent / paintEvent ..."]
        X["事件被吞掉，到此为止"]
    end
    P1 --> Q
    Q --> L --> D --> N
    P2 --> N
    P3 --> N
    N --> F
    F -- "过滤返回 true" --> X
    F -- "放行" --> E --> H

一句话总结：事件系统 = postEvent 往 receiver 线程的队列投包裹 → exec 的事件循环不停取件 → sendEvent → notify → 过滤器安检 → event() 按 type 分发到具体 handler。Queued 信号槽、定时器、deleteLater 全是跑在这条流水线上的不同包裹。
