Qt 性能优化指南

在使用 Qt 开发应用时，对字符串的处理和对大量数据的渲染往往是性能瓶颈。本文总结了这几类常见场景的优化策略。

1. QStringBuilder 字符串拼接优化

频繁的 QString 拼接（使用 + 运算符）会导致多次内存分配和字符串拷贝，影响性能。

可以通过引入 <QStringBuilder> 使用 % 替代 +，底层会先计算总长度，只分配一次内存。

2. QStringLiteral 编译期字符串

对于代码中的字符串常量，不要直接写 "..." 或 QString("...")，应使用 QStringLiteral 宏。

  • 原理：编译器会在编译阶段直接生成 QString 所需的内部数据结构，并放在只读数据段中。
  • 优势：程序运行时零内存分配（无需 new）且零拷贝（避免 UTF-8 运行时解码）。
TIP

仅在处理字符串常量时使用 QStringLiteral。对于会动态变化的字符串，使用常规构造或 QStringBuilder 即可。

3. 海量数据展示 (Model/View 架构)

当需要展示成千上万甚至百万条数据时，**严禁使用 QTableWidget 或 QListWidget**，这会为每个单元格创建一个 UI 控件，导致严重的卡顿和内存暴涨。

正确做法：使用 QTableView / QListView 配合自定义继承自 QAbstractTableModel 的数据模型，实现数据的按需渲染（仅绘制屏幕可见区域的数据）。

WARNING

对于 QTableWidget / QListWidget，Qt 内部使用 QTableWidgetItem 并且为每个元素实例化对象，不适合超过万级别的数据项。
