C++ 无锁队列与对象池高性能内存管理

工业相机高频采集（100fps+）的两个瓶颈：new/delete 的内存碎片与延迟，std::mutex 的上下文切换与丢帧。

解法：对象池复用内存，无锁队列跨线程传递。

1. SPSC 无锁队列（环形缓冲区）

单生产者（采集线程）→ 单消费者（算法线程）。

关键设计解析

head_ / tail_ 只增不减：用无符号整数自然溢出回绕，取模靠 & (Capacity-1) 映射到实际下标。不需要额外的回绕处理逻辑。

**t - head_ == Capacity 而非 t == head_ + Capacity**：减法在无符号整数下天然正确——即使 head_ 发生过回绕，差值仍然正确。比较法则会溢出出错。

relaxed 读自己、acquire 读对方：

  • tail_.load(relaxed) — 生产者读自己的写指针，无竞争，relaxed 足够
  • head_.load(acquire) — 生产者读消费者的读指针，必须看到最新值，否则误判满而丢数据

release 写：tail_.store(release) 保证 buffer_ 的写入在 tail_ 更新前完成，消费者 acquire 读到新 tail_ 时一定能看到完整的数据。

NOTE

为什么 alignas(64)？
消除伪共享（False Sharing）：CPU 缓存行 64 字节，head_ 和 tail_ 若在同一行，一个核写 tail_ 会使另一个核的 head_ 缓存失效，两核无意义地竞争同一缓存行。alignas(64) 强制分处不同缓存行。

2. 智能对象池（自动回收）

关键设计解析

两个 vector 的分工：

  • pool_storage_：unique_ptr 持有真实内存所有权，池存在期间绝不释放
  • available_：裸指针队列，只做借还登记

这是安全性的根基——即使 available_ 出 bug（重复归还），也不会 double free，因为真正的 delete 只在 pool_storage_ 析构时发生。

ObjectDeleter 机制：
SmartPtr 本质是 unique_ptr<T, ObjectDeleter>，析构时调 returnObject(ptr) 归还而非 delete。returnObject 是 private，归还逻辑完全由生命周期控制，外部无法手动干预。

NOTE

为什么 unique_ptr 而非 shared_ptr？

  • 语义匹配：一帧同一时刻只有一个拥有者（采集→队列→渲染），move-only
  • 确定性回收：离开作用域立即归还，无引用计数延迟
  • 零开销：shared_ptr 每次拷贝原子操作，高频路径上的无意义负担

池耗尽：返回 nullptr，调用方应检查并降级（丢帧/等待/扩容）。

3. Qt QImage 零拷贝渲染

此构造函数不拷贝像素数据，仅保存裸指针引用。4096×3000 灰度图（~12MB）省去一次 memcpy。

生命周期陷阱

QImage 持有裸指针——若原始内存被对象池回收，指针悬空 → 花屏/crash。

解法：SmartPtr 锁住生命周期

帧替换流程

current_frame_ = std::move(frame) 执行时：

  1. 旧帧析构 → SmartPtr 触发 returnObject → 自动归还池
  2. 接管新帧
  3. 重建 render_image_（零拷贝引用新帧像素数据）
  4. update() → paintEvent 渲染

旧帧归还后可能被下一次 acquire 复用，但此时 render_image_ 已指向新帧，无竞态。
