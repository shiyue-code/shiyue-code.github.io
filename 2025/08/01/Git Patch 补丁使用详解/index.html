Git Patch（补丁）完整使用指南

Git Patch 用于记录和共享代码变更，它将代码差异打包成文本文件。这在跨物理网络、在无法访问同一远程仓库的团队间传递和应用修改时非常有用。

Git 提供了两种主要形式的 Patch：

  1. git diff 生成的补丁：只包含纯代码差异，不包含提交历史（作者、时间、提交信息）。
  2. git format-patch 生成的补丁：标准的邮件形式补丁，保留了完整的提交历史和作者元数据。

1. 创建 Patch

A. 使用 format-patch 创建提交补丁（带提交历史）

B. 使用 diff 创建未提交更改的补丁（纯代码差异）

2. 应用 Patch

根据补丁的生成方式，应用补丁的方式也有所不同。

A. 应用 format-patch 补丁（推荐，使用 git am）

git am（Apply Mailbox）会自动将补丁作为新提交直接应用并提交到您的历史树中，自动保留原作者和提交信息。

B. 应用 diff 补丁（使用 git apply）

git apply 只将修改应用到工作区或暂存区，不生成新的提交。

6. 小贴士（Tips）

  1. 二进制文件处理：默认情况下，git diff 和早期的补丁可能无法妥善记录二进制文件变化。对于图片或编译产物，请始终使用 git format-patch。
  2. 签名证书：团队协作中，可以使用 git format-patch -s HEAD~1 生成带签名的补丁（Signed-off-by），方便追溯责任人。
  3. 协作流程：
    • 离线开发者：修改代码 -> git diff > fix.patch -> 微信/邮件发送补丁。
    • 接收方：git apply --check fix.patch -> 验证无误 -> git apply fix.patch -> 代码合并。
