Git Rebase（变基）深度指南

git rebase 用于将一个分支上的修改“重新基地化”到另一个分支上。与 git merge 不同，Rebase 会修改提交历史，创造出一条干净、线性的历史提交线。

1. 基础用法：消除分支分叉

在特性分支开发完毕、准备合并回主分支前，可以变基到最新的主分支，使提交历史保持一条直线：

IMPORTANT

变基黄金法则：
绝对不要在公共分支（例如已推送到远程且有其他人协同开发的 main/master 或 release 分支）上进行 Rebase。
重写公共分支的历史会导致其他协作者的提交树发生严重错乱！

2. 交互式变基：合并与整理提交历史

交互式变基（git rebase -i）允许我们在提交合并前对历史记录进行修剪、合并或删除。

在打开的文本编辑器中，你可以调整每次提交前面的关键字：

动作关键字 简称 作用 适用场景
pick p 保留该提交（默认操作） 无需修改的提交
squash s 保留该提交，但将其合并到前一个提交中，保留两个提交的注释信息 整合功能相关的零碎提交
fixup f 类似于 squash，但合并时直接丢弃当前提交的注释信息 合并用于修复 bug 的琐碎提交
edit e 暂停变基，允许你修改此提交的内容，或拆分该提交 修改旧的提交代码或历史说明
drop d 彻底丢弃/删除该提交 移除误提交的文件或敏感数据
